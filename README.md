# 変換ツール

公開URL（同じ中身が2か所にあります）

- Cloudflare Pages: https://media-shrink.pages.dev
- GitHub Pages: https://squad-customersupport.github.io/media-shrink/

タブで3つのツールを切り替えます。どれも変換はブラウザ内で完結し、ファイルはどこにも送信されません。**Chrome専用。**

## 1. animated webp にする

mp4を、指定サイズ（初期値500KB）以下のanimated webpに変換します。

横幅350px・画質0.9・12fpsで書き出してみて、超えていたら以下の順に1段ずつ下げ、最初に収まった時点で止めます。

1. fps（12 → 10 → 8 → 6 → 5 → 4 → 3 → 2）
2. 画質（0.85 → 0.8 → ... → 0.3）
3. 横幅（320 → 288 → ... → 160）

画質を優先したいので、fpsから先に落とす設計です。fpsを落としすぎたくない場合は、切り出し範囲（開始秒・終了秒）を狭めて尺そのものを短くします。

animated webpの組み立て（VP8Xチャンク、ANIMチャンク、フレームごとのANMFチャンク）は外部ライブラリを使わず自前でRIFFを書いています。ここが一番壊れやすい箇所なので、再生できない動画が出たらまずここを疑ってください。

## 2. mp4 を軽くする

mp4を、指定サイズ（初期値1MB）以下のmp4に作り直します。

こちらはビットレートを直接指定できるので、webpのような総当たりはしません。目標サイズと尺から必要なビットレートを逆算し、それに見合う横幅を600px〜350pxの範囲で選びます。

横幅の決め方は「1画素1フレームあたり何ビット割けるか」です。ビットレートが決まっているとき、600pxに広げると1画素あたりが薄くなってブロックノイズが出て、350pxなら細部は失われるものの各画素はきれいに出ます。`MIN_BPP`（0.07）を下回らない範囲でいちばん大きい横幅を選びます。

エンコーダーは指定ビットレートちょうどには収まらないので、書き出した結果が目標を超えていたらビットレートを下げて作り直します。最大3回。

音声は初期状態で捨てます。残す場合は64kbpsを確保し、そのぶん映像に回せる分が減ります。

## 3. 画像を軽くする

jpg / png を、指定サイズ（初期値999KB）以下の webp または jpg に変換します。

横幅600px・画質0.92で書き出してみて、超えていたら以下の順に1段ずつ下げ、最初に収まった時点で止めます。

1. 画質（0.85 → 0.78 → 0.70 → 0.62 → 0.54 → 0.46 → 0.38 → 0.30）
2. 横幅（480 → 384 → 350）

動画タブと同じで、横幅を削るのは最後の手段です。

実際には600px・999KBならほぼ1手目で収まるので、段階を下げる仕組みは保険として動くだけになります。上限をもっと絞ると総当たりが働きます。

出力形式は webp と jpg から選べます。webpの方が同じ画質で軽いので基本はこちらですが、古い環境に配る場合のために jpg も残しています。

png の透過は、画像の四隅と中央あたりをサンプリングして検出します。透過があるのに jpg を選んだ場合は「白で塗りつぶされます」と警告を出します。webpなら透過は保たれます。

元画像より大きくはしません。読み込んだ時点で、横幅の初期値を元画像の幅に合わせます。

変換は `canvas.toBlob()` に任せているだけなので、animated webpタブと違って自前でバイナリを組み立てている箇所はありません。壊れにくい代わりに、圧縮率はブラウザの実装任せです。

## ファイル

- `index.html` — 3つのツールの全部。単体でブラウザに開いても動く
- `mediabunny.min.mjs` — mp4の読み書きに使うライブラリ（Mediabunny, MPL-2.0）。CDNに頼らず同梱している。画像タブは使わない
- `LICENSE-mediabunny.txt` — 上記のライセンス全文

## 直しかた

1. GitHubで `index.html` を開き、鉛筆アイコンから編集する
2. Commit changes を押す
3. 1分ほどでGitHub Pagesに反映される

**Cloudflare Pages は自動では反映されません。** GitHubとは連携しておらず、ファイルを直接置く方式で公開しているためです。Cloudflare側も直すには、リポジトリを手元に落として次を実行します。

```
npx wrangler pages deploy . --project-name media-shrink --branch main
```

（`README.md` や `notes/` も一緒に上がりますが、公開されて困るものではありません。厳密に3ファイルだけにしたい場合は `index.html` / `mediabunny.min.mjs` / `LICENSE-mediabunny.txt` を別フォルダにコピーしてそのフォルダを指定してください。）

どちらか一方だけを使う運用にするなら、使わない側の公開を止めたほうが、古い方を見てしまう事故を防げます。

ローカルで直す場合、`index.html` はESモジュールを読むので `file://` で開くとCORSで止まります。フォルダで `python3 -m http.server` を立てて開いてください。
